### Product changes

- **Rule tiering** (`src/core/rules/registry.ts`): `tier: "commercial" | "health"`. Three
  commercial rules lead the queue; the eight hygiene checks sit under a "Site health" break.
  On the real corpus the split is **6 commercial / 24 health** — that ratio was the problem.
- **Client-side value** (`src/core/clientValue.ts`): `Client.averageJobValue` yields
  *"Pays for itself with one job."* Pure arithmetic on an agency-entered number. No model, no
  estimate, and **nothing at all** when the value is not recorded.
- **Outcome tracking** (`src/core/winRates.ts`): `sold` is a first-class opportunity status with
  an optional amount. Distinct from dismissed/covered/resolved. The queue orders by what this
  agency converts; Settings → Check health shows the history. Sold findings are suppressed from
  re-analysis so a re-run cannot overwrite the record of a win.
- **Client drift detection** (`src/core/offeringDrift.ts`): every analysis run stores the service
  labels suggested by its evidence. The first exhaustive crawl is a silent baseline; later
  exhaustive scheduled crawls surface only newly observed labels in `/changes`. Manual and
  incomplete crawls never emit drift, and the signal is advisory rather than an Opportunity.
  Storage is additive in `migrations/0021_offering_drift.sql`; the flow is covered by
  `test/core.offeringDrift.test.ts`, `test/db.portfolioChanges.test.ts`, and the analysis-run
  integration test.

### Finding-quality audit (the important part)

Every one of the 30 findings the engine produced on the 24-site corpus was checked against the
cached HTML. **Two real bugs**, both fixed with regression tests:

1. **`broken-internal-link` was 100% wrong.** It fired exactly once across 24 sites:
   `/cdn-cgi/l/email-protection` — Cloudflare's email obfuscation, which 404s to a bot and is
   rewritten to a working `mailto:` by Cloudflare's own script. Fixed via
   `isPlatformInfrastructurePath` in `src/core/siteStructure.ts`, applied in both the rule and the
   crawl frontier. Test: `test/core.platformPaths.test.ts`.
2. **A third of commercial findings were false.** Two dental sites were told *"No page for
   Invisalign clear aligners"* — one at **90% confidence** — while their `/invisalign/` page was
   linked from every page. `hasSignature` in `src/core/absenceVerification.ts` was gated behind
   `score >= 0.5`; a three-token offering matched by a one-token slug scored 0.33, so the one word
   that identified the page was discarded. Test: the "corpus audit regressions" block in
   `test/core.absenceVerification.test.ts`.

Also tightened: `no-service-pages` said *"none of them describes a service"*, which atlasplumbing.ca
disproves (its Toronto page has a services section). Now *"not one of them is dedicated to a single
service"* — provable, and a sharper insight.

**Verified sound:** the four surviving commercial findings (kids-connect, atlasplumbing,
cambridgeheating ×2). One earlier suspicion of mine was wrong: cambridgeheating's "Our Services"
link is inside an HTML comment, so the parser was right to ignore it and `crawlExhaustive: true`
is accurate.

### Competitor service gaps — **complete**

The first rule that reads a site the client does not own.

- `src/core/competitorGaps.ts` — pure gap analysis. Honesty rules: **two** competitors minimum
  (one is that competitor's choice, not a pattern); an **unreadable** competitor is excluded from
  the count entirely, never scored as "does not have it"; a `limitation` string is returned instead
  of an empty result, because "no gaps found" would read as "your client is level with the market".
- `src/db/competitors.ts` + `migrations/0020_competitors.sql` — capped at 3 per client
  (`MAX_COMPETITORS_PER_CLIENT`, defined in the **core** module so components can import it without
  pulling in database code). Composite FK, like every other tenant table.
- `app/lib/competitors.server.ts` — a **separate explicit action**, not part of every analysis:
  one comparison crawls up to three whole sites, so folding it in would triple the cost of the
  most-pressed button invisibly. Takes a slot from the same admission ledger.
- Every gap goes through the **same judgment gate** (`judge()` now covers
  `competitor-service-gap`), because a label scraped from a competitor's navigation is no more
  trustworthy than one typed into an offerings box — "Free Quotes" appears in both.
- UI on the client page: name competitors, remove them, "Compare". Verified in the design harness.
- Tests: `test/core.competitorGaps.test.ts` (10), `test/competitors.compare.test.ts` (11).

## 2. What is left — two features, agreed but not built

The user asked for all four. **Competitor gaps and client drift detection are done; these two remain.**

Context for whoever picks this up: the audit measured **4 commercial findings across 24 sites** —
about one sellable finding per six clients. That is the constraint these features exist to attack.
Anything that only adds more hygiene checks makes the product worse, not better.

### A. Deeper conversion-path rules

**Goal:** widen the one commercial rule that is revenue-linked rather than structural.

Candidates, all evidenced by data the crawler already collects (`EvidencePage.forms`,
`EvidenceLink.scheme`, `wordCount`):
- a service page with no form, no `tel:` and no CTA link at all;
- a contact page with no form;
- a phone number present as text but never as a `tel:` link (mobile users cannot tap it) —
  **check whether `textExcerpt` is complete enough**; it may be truncated, in which case this one
  needs a parser change and should be dropped rather than done badly.

**Shape:** extend `src/core/rules/brokenConversionPath.ts` or add siblings next to it. They are
commercial-tier. Add each to `RULE_SERVICE_LINKS` and `STARTER_DEFAULTS` in
`app/routes/onboarding.tsx` — **both are type-enforced**, so a missing entry is a compile error,
which is the intended guard rail.

### B. Seasonal service calendar

**Goal:** a recurring reason to look, attacking the day-one-decay problem.

**The tension to respect:** this is the one feature that is advisory rather than evidence-derived,
and the product's entire credibility rests on refusing to guess. Recommended framing: it is a
**prompt, never a finding**. It must not become a priced Opportunity. Something like — *"You record
'boiler servicing' for this client. It is September; that is the month it matters most."* That is
arithmetic on the agency's own recorded offerings plus a calendar, not a prediction about the
market.

**Shape:** a curated `vertical → month → emphasis` table in `src/core/` (pure, testable), surfaced
on `/changes`. Keep it small and hand-written; a large speculative table is where this feature goes
wrong.

## 4. How to work on this codebase

The three loops that caught every real bug in this session, in order of value:

```bash
pnpm verify                     # the gate: safety, preflight, tests, typecheck, build
pnpm analyzability --offline    # 24 real sites, replayed. Watch "false analyzable", not just exit code
pnpm tsx scripts/analyzability/ui-fixture.ts
pnpm tsx scripts/design-harness.tsx build/client/harness   # then open build/client/harness/*.html
```

**The design harness caught four defects this session** that tests did not: two stale fixtures, CSS
classes that did not exist, `"$9,400 – $9,400"`, and a subtitle that had quietly become false. It
renders the real route components with `loaderData` as a prop, so it needs no session. When you add
a loader field, **add it to the harness fixture too** — or default it in the component, which is
better, because loader data is a boundary.

**Auditing findings** — the technique that found both engine bugs. `.analyzability-ui.json` holds
every finding for the corpus; `.analyzability-cache/` holds the raw HTTP responses. Read a finding,
then go and read the HTML it claims to be about. Do not trust a regex over the raw body — I
accused the crawler of missing a page that turned out to be inside an HTML comment.

**Migrations** are additive only; `test/production.migrations.test.ts` lists them explicitly and
`src/db/schema.ts` must mirror them (`test/db.schema-parity.test.ts` enforces it). Latest is
`0020_competitors.sql`.
